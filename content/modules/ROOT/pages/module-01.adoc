= Vulnerability Scanning with Grype

.*Module Overview*
[sidebar]
--
*Duration:* 8-10 minutes +
*Learning Objectives:*

* Enable the rootless Podman socket for API-based tools
* Scan a hardened container image for CVEs using Grype
* Compare vulnerability counts between a hardened image and a UBI-based image
* Understand the security benefits of minimal base images
--

[[introduction]]
== Introduction

Building secure images is only the first step. In this module, you'll learn how to analyze the security posture of your container images using industry-standard tools.

Two images are already pre-built and waiting for you:

* `rhhi-demo:v1` — a Flask web app built using Red Hat Hardened Images as the runtime base (`hi/python:3.12`), with a multi-stage build that installs only what the application needs at runtime
* `rhhi-demo:ubi` — the same Flask app built from the standard UBI Python image (`ubi9/python-312`), a single-stage build with a broader set of base packages

Both images run the same application code and the same version of Python 3.12. The only difference is the base image. You'll use `grype` to scan both for known CVEs and see firsthand how the choice of base image affects your security posture.

[[podman-socket]]
== Step 1: Enable the Podman Socket

Grype and Syft use the Podman API socket to find and inspect images. As a rootless user, you can enable this socket just for your session — you don't need system-level access.

[source,bash,role=execute]
----
systemctl --user enable --now podman.socket
----

[NOTE]
====
This enables the socket for the current user session only. It does not require `sudo` or root privileges. This is a key feature of rootless Podman: the daemon socket runs entirely within your user namespace.
====

[[verify-tools]]
== Step 2: Verify the Scanning Tools

Both `grype` and `syft` are already installed. Let's confirm they're ready:

[source,bash,role=execute]
----
grype version
----

[source,bash,role=execute]
----
syft version
----

You should see version output for both tools. Now let's check the images:

[source,bash,role=execute]
----
podman images rhhi-demo
----

----
REPOSITORY           TAG         IMAGE ID      CREATED        SIZE
localhost/rhhi-demo  ubi         8f3a1c2d4e5f  2 minutes ago  271 MB
localhost/rhhi-demo  v1          9b2e4f6a7c8d  2 hours ago    108 MB
----

Notice the size difference: the hardened multi-stage image is smaller because the builder stage dependencies are not included in the final image.

[[scan-hardened]]
== Step 3: Scan the Hardened Image

Use Grype to scan `rhhi-demo:v1` for known CVEs:

[source,bash,role=execute]
----
grype rhhi-demo:v1 --by-cve
----

[NOTE]
====
The scan may take 1-2 minutes to complete. The `--by-cve` flag normalizes output to CVE identifiers instead of other data sources like GHSA, making it easier to cross-reference with other tools and databases.
====

.*Expected output:*
----
 ✔ Loaded image                                           rhhi-demo:v1
 ✔ Parsed image sha256:9b2e4f6a...
 ✔ Cataloged contents  a3c7d9e1...
   ├── ✔ Packages                        [82 packages]
   ├── ✔ File metadata                   [531 locations]
   ├── ✔ Executables                     [74 executables]
 ✔ Scanned for vulnerabilities     [0 vulnerability matches]
   ├── by severity: 0 critical, 0 high, 0 medium, 0 low, 0 negligible
   └── by status:   0 fixed, 0 not-fixed, 0 ignored
No vulnerabilities found
----

[NOTE]
====
Hardened base images typically have **zero or near-zero CVEs** at ship time. Results may vary slightly over time as new CVEs are discovered against any component.
====

[[scan-ubi]]
== Step 4: Compare with the UBI Image

Now scan the UBI-based version to see the difference:

[source,bash,role=execute]
----
grype rhhi-demo:ubi --by-cve --only-fixed
----

.*Expected output (varies, but typically):*
----
 ✔ Loaded image                                           rhhi-demo:ubi
 ✔ Parsed image  sha256:8f3a1c2d...
 ✔ Cataloged contents   c4b8e2f5...
   ├── ✔ Packages                        [213 packages]
   ├── ✔ Executables                     [185 executables]
   ├── ✔ File metadata                   [1,842 locations]
 ✔ Scanned for vulnerabilities     [8 vulnerability matches]
   ├── by severity: 0 critical, 2 high, 4 medium, 2 low, 0 negligible
   └── by status:   8 fixed, 12 not-fixed, 0 ignored
<output truncated>
----

[NOTE]
====
The `--only-fixed` flag shows only vulnerabilities that have available patches. This focuses attention on immediately actionable issues rather than `wontfix` items. Remove the flag to see the full vulnerability list including unfixed issues.
====

[IMPORTANT]
====
**Key Insight:**

* **Hardened image** (`rhhi-demo:v1`): 0 CVEs at ship time
* **UBI image** (`rhhi-demo:ubi`): CVEs from general-purpose packages included in the standard UBI Python image

Both images run the same Flask app on the same Python 3.12. The CVE difference comes entirely from the base image — the hardened runtime includes only what a Python application needs at runtime, while UBI includes a broader set of packages to support general-purpose workloads. Every extra package is a potential CVE surface.
====
